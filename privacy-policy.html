Privacy Policy — Voice Family Phone / Családi Telefon

Effective date: 1 October 2026

Voice Family Phone ("Családi Telefon", "the app") is designed to make calling a small, preconfigured family contact list simple and accessible. This policy describes the current Android version.

Data stored by the app

The current version does not require an online account and does not operate a developer backend.

The following information may be stored locally in the app's private storage on the device:

  • up to six contact names;
  • relationship labels and spoken aliases;
  • telephone numbers;
  • a reference to a contact photo selected by the caregiver;
  • speech feedback preferences;
  • the enabled/disabled state of the local wake-word feature;
  • confirmed post-call family-message text and local delivery state;
  • protected-mode state and caregiver PIN verification data (salted hash, never the PIN itself);
  • whether the managed family member is marked as physically able to operate the phone, and the related simple-lockscreen preference;
  • child-mode age, daily schedule and parent-configured feature rules when Child mode is enabled;
  • the most recent safety location snapshot when location sharing is enabled.

Wake-word diagnostic counters are used only for local testing during the running app session and are not uploaded by the app.

Microphone and speech recognition

The app requests microphone access only for voice features.

For supported languages, the optional wake-word feature uses Android's explicitly on-device speech recognizer. The app does not provide a cloud fallback for continuous wake-word listening. Unsupported languages do not enable an unverified fallback wake word.

For user-initiated push-to-talk commands and post-call message dictation, the app prefers Android's on-device recognizer when it is available. If an on-device recognizer is unavailable, the app can use the device's configured system speech-recognition service while requesting offline processing. The actual behavior of that system service is controlled by the device and its speech-recognition provider, and on some devices speech audio may therefore be processed by that provider outside the device.

The app itself does not save raw microphone audio or intermediate speech-recognition hypotheses. When the user dictates a post-call family message, the recognized text is shown for confirmation; only the confirmed message text is stored locally.

Telephone calls

When the user or caregiver initiates a call, the app passes the selected preconfigured telephone number to Android's telephony system. The mobile network operator and phone platform process the call according to their own terms and privacy practices.

The app can optionally be selected by the user as the device's default Phone app. In that mode it provides the incoming and ongoing call interface. For an incoming call it can announce the caller and ask whether the user wants to answer; the call is answered or rejected only after an explicit voice response or button press.

The app does not read call history and does not request SMS or call-log permissions. Because normal Android telephony does not provide this app with reliable rejected/busy/no-answer status for calls placed through another dialer, the post-call message flow still asks the user whether they were able to speak.

Family messages

If the user says they could not reach a family member, the app can invite them to dictate a short message. The recognized text is presented to the user before it is saved.

In the current version, confirmed messages are stored locally in the app's private storage. Cross-device delivery is not enabled until authenticated family-device pairing and a secure transport are implemented. The app does not silently fall back to SMS and does not request SMS or call-log permissions for this feature.

Device contacts

The caregiver may optionally grant Contacts access. This is used only during an incoming call to look up the caller's display name when the number is not one of the configured family contacts. The contact list is not copied into the app, uploaded to a developer server, used for advertising, or used to build a profile.

If Contacts access is denied, incoming calls still work; callers outside the configured family roster are announced as unknown.

Photos

A caregiver may select a photo for a configured family contact. The app stores a local reference to the selected photo so it can display that image. The current version does not upload contact photos to a developer server.

Protected phone mode and caregiver control

On a deliberately provisioned managed device, the app can operate in a protected Device Owner / Lock Task mode. This keeps Family Phone as the managed home interface and limits accidental access to other device functions.

Caregiver settings can be protected by a local 4–8 digit PIN. The app stores only a salted cryptographic hash of that PIN.

The remote-control protocol is designed around a paired caregiver public key. Remote lock, temporary unlock and location-request commands must be signed, time-limited and monotonically sequenced to prevent replay. The current version does not yet operate the backend/push transport that would carry these commands between devices.

Simple lockscreen and mobility setting

The caregiver can mark whether the managed family member is physically able to operate the phone. This local setting is used only to decide whether the optional Simple Lockscreen may be enabled.

If the family member is not marked as mobile, the Simple Lockscreen is automatically disabled. The Simple Lockscreen is an accidental-touch guard and does not replace Device Owner protection or the caregiver PIN.

This mobility setting remains in app-private local storage in the current version and is not sent to a developer backend.

Child mode

A parent or caregiver may enable Child mode. The app can store the child's age in years, wake/school/bedtime schedule, and parent-defined rules that determine which device functions may be opened during school time, free time, or night.

These settings are stored locally on the managed device. The app does not create an advertising profile from the child's age or schedule, and the current version does not send these settings to a developer backend.

Family calling and the reserved SOS safety capability are not disabled by the time-of-day rule engine.

Safety location sharing

The caregiver may enable location access for safety use. While enabled, the app keeps only the latest known location snapshot in app-private storage, together with accuracy, capture time and battery percentage when available. The current implementation does not maintain a full location history.

No location is sent to a developer server in the current version because the secure paired-device transport is not yet active. A later release that enables cross-device location delivery must update this policy and the Play Data Safety declaration before distribution.

Google Play purchases

The optional Family Phone Full upgrade is sold as a one-time digital purchase through Google Play Billing. Purchase processing, receipts and payment information are handled by Google Play. The app queries Google Play for the purchase state needed to determine whether the Full features are available. The developer does not receive or store payment-card details.

Analytics, advertising and tracking

The current version contains no advertising SDK, analytics SDK, cross-app tracking SDK, or developer-operated telemetry service.

Sharing

The developer does not sell user data and does not currently operate a backend service that receives the locally stored contact or family-message data.

Some user-initiated functions rely on Android system services or external service providers, such as the mobile network operator, Google Play Billing and, on devices where local recognition is unavailable, the configured system speech-recognition provider.

Permissions

The current version may request:

  • Microphone (RECORD_AUDIO): voice commands, post-call message dictation and the optional local wake word.
  • Phone calls (CALL_PHONE): placing a call.
  • Contacts (READ_CONTACTS, optional): resolving an incoming caller's display name when that caller is not one of the configured family contacts.
  • Notifications (POST_NOTIFICATIONS, where required): displaying incoming-call notifications and the full-screen call UI.
  • Full-screen call intent (USE_FULL_SCREEN_INTENT): showing the incoming call interface while the app is the user-selected default Phone app.
  • Location (ACCESS_COARSE_LOCATION / ACCESS_FINE_LOCATION, optional): maintaining the latest safety location when the caregiver enables location sharing.
  • Foreground service (FOREGROUND_SERVICE / FOREGROUND_SERVICE_LOCATION): keeping safety location updates active while location sharing is enabled.

Permissions are requested when a feature needs them. Denying a permission prevents the corresponding feature from operating.

Data retention and deletion

Locally configured contacts, messages, protected-mode settings and the latest location snapshot are stored in app-private storage. Contacts can be removed from caregiver settings. Disabling location sharing stops location updates; clearing app storage or uninstalling removes the stored location snapshot and all other app-private data.

Because the current version has no developer account or developer backend, there is no server-side user profile to delete.

Security

The app minimizes permissions, disables cleartext network traffic, does not log phone numbers or raw speech-recognition hypotheses by design, and restricts voice calling to the configured contact roster.

Changes to this policy

If future versions add remote pairing, cross-device message delivery, video calling, cloud services, accounts, analytics, or other network features, this policy and the Google Play Data Safety declaration must be updated before those features are distributed.

Privacy contact

Privacy inquiries should be sent through the developer contact mechanism published with the app's Google Play listing.

Publication requirement

For Google Play submission, this privacy policy must be published at an active, publicly accessible, non-geofenced HTTPS URL. A link to a private repository is not sufficient.
